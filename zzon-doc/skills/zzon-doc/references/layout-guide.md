# 배치 가이드 — 선이 겹치지 않고 한 방향으로 읽히는 그림

엔진은 자동으로 배치한다. 그래도 어느 것이 주 경로이고 어느 것이 곁가지인지는 엔진이 모른다. 그 의도를 작성자가 힌트로 알려 줘야 그림이 정돈된다. 이 문서는 DSL을 쓸 때 배치를 잡는 순서와, `bun ia check` 결과가 나쁠 때 고치는 법을 정한다.

## 1. 원칙

- **읽는 방향은 하나다.** 요청이 들어와 처리되고 저장되는 흐름은 왼쪽에서 오른쪽, 위계나 절차는 위에서 아래로 읽힌다.
- **열은 단계, 줄은 같은 단계의 형제다.** 주 경로는 한 줄에 곧게 놓고, 예외와 보조 경로는 그 아래 줄에 둔다.
- **선은 짧고 곧게.** 꺾임이 많거나 다른 노드를 크게 돌아가는 선은 배치가 의도와 어긋났다는 신호다.
- **캔버스는 필요한 만큼만 크다.** 간격을 넓히는 일은 엔진이 한다(3절). 작성자는 구조를 정한다.

## 2. 작성 순서

1. **방향을 정한다.** `diagram(…, { direction })`에 적는다. 상태 전이도와 화면 흐름은 RIGHT, 플로우차트·모듈 의존성·도메인 모델은 DOWN이 기본값이다. 인프라와 데이터 흐름은 요청이 지나가는 방향(보통 RIGHT)이다.
2. **주 경로를 열로 놓는다.** 진입점을 `hints: { layer: 0 }`으로 두고, 대표 경로의 다음 노드마다 layer를 하나씩 올린다. 대표 경로 하나만 정해도 나머지는 엔진이 맞춘다.
3. **같은 열 안의 줄을 정한다.** 주 경로는 `order: 0`(기본값)이고, 예외·취소·보조 경로는 `order: 1` 이상으로 아래에 둔다.
4. **묶는다.** 같은 역할의 반복(크론 4개, 워커 3개)은 노드 하나에 `sublabel: "×4"`로 적는다. 계정·VPC·도메인 같은 구역은 그룹으로 감싼다. 한 그룹의 구성원은 같은 열에 모여야 상자가 겹치지 않는다.
5. **횡단 관심사는 아래 띠로 보낸다.** 모니터링·시크릿·IAM은 `d.band("bottom", …)`에 넣고 선을 긋지 않는다. 관심사가 보안이나 운영인 그림이면 예외다.
6. **되돌아가는 선은 표시한다.** 재시도, "쇼핑 계속"처럼 앞 단계로 돌아가는 선은 `back: true`로 둔다. 배치는 정방향을 유지하고 선만 거꾸로 그린다.
7. **선이 몰리는 곳을 푼다.** 한 노드에서 선이 5개 넘게 나가면 중간 노드(게이트웨이·큐)를 두거나 목적지를 묶는다. 같은 목적지로 가는 선 여러 개는 `hints: { bundle: "이름" }`으로 한 줄기로 모은다.
8. **라벨은 두 어절 이하로 쓴다.** 긴 설명은 `description`에 넣는다(사이드바). 라벨이 길면 통로가 넓어지고 다른 선을 가린다.
9. **진입면은 마지막에 고정한다.** 선이 노드를 크게 돌아가면 `hints: { sourceSide: "E", targetSide: "W" }`로 나가고 들어오는 면을 정한다.

```ts
// 주 경로를 열로 세우고, 예외는 아래 줄로
const api = d.node("api", { icon: "api-gateway", label: "API", hints: { layer: 0 } });
const fn = d.node("fn", { icon: "lambda", label: "주문 처리", hints: { layer: 1 } });
const db = d.node("db", { icon: "aurora", label: "주문 DB", hints: { layer: 2 } });
const dlq = d.node("dlq", { icon: "sqs", label: "실패 큐", hints: { layer: 2, order: 1 } });
```

## 3. 캔버스 크기 — 엔진이 맞추는 것

- **간격:** 배치하고 선을 그은 뒤 선 겹침(서로 다른 선이 6px 안으로 나란히 붙음)이나 라벨 가림을 잰다. 하나라도 있으면 간격을 1.35배, 그래도 남으면 1.7배로 넓혀 다시 배치하고 가장 깨끗한 결과를 쓴다. 겹침이 없는 그림은 원래 크기 그대로다.
- **통로 폭:** 열 사이 통로는 가장 긴 라벨과, 같은 이웃 사이를 지나는 선 수에 맞춰 넓어진다.
- **보여 주는 창:** 위키에 넣은 그림은 그림의 가로세로 비율에 맞춰 높이가 정해진다(320~720px). 넓은 그림은 낮게, 키가 큰 그림은 높게 보인다.
- **작성자가 할 일:** 한 장에 억지로 넣지 않는다. 등급과 큰 그림 판단(`selection-rubric.md` §3, §3.4)을 따른다. 간격을 넓혀도 남는 겹침은 구조 문제라서 2절로 돌아가 고친다.

## 4. 검사 결과별 처방

| `bun ia check` 항목 | 뜻 | 고치는 법 |
|---|---|---|
| 선 겹침 | 서로 다른 선이 같은 통로에 붙어 달린다 | 열을 나눈다(`layer`). 같은 목적지 선은 묶는다(`bundle`). 선이 몰리는 노드 앞에 중간 노드를 둔다 |
| 엣지당 교차 | 줄 순서가 엇갈렸다 | 연결된 노드끼리 같은 줄에 둔다(`order`). 진입면을 고정한다. 교차가 몰리는 그룹을 옆 열로 옮긴다 |
| 엣지당 꺾임 | 이어진 노드의 줄이 어긋났다 | 주 경로 노드를 모두 `order: 0`에 둔다. 한 칸씩 건너뛰는 선이 많으면 열을 다시 센다 |
| 라벨 가림 | 다른 선이 라벨을 지난다 | 라벨을 줄이거나 지운다. 라벨이 붙은 선의 진입면을 바꾼다 |
| 종횡비 | 한 방향으로 너무 길다 | 방향을 바꾸거나, 열 수를 줄이거나, 큰 그림과 세부로 나눈다 |
| 엣지 없는 노드 | 관계가 빠졌거나 주석이다 | 관계를 선으로 긋는다. 주석이면 사이드바 설명으로 옮긴다 |
| 노드 수·엣지 수 초과 | 한 장에 너무 많다 | 축소 사다리(§3.3), 큰 그림과 세부(§3.4) |
| 줌 판단 "다시 구성하라" | 묶음 구조가 없거나, 접으면 선이 끊긴다 | 계정·도메인·계층 단위로 그룹을 다시 짜고, 그룹 사이 관계를 선으로 긋는다 |

## 5. 마지막 확인

- PNG를 열어 눈으로 본다. 선을 손가락으로 따라가며 주 경로가 한 방향으로 읽히는지, 같은 줄에 있어야 할 노드가 들쭉날쭉하지 않은지 본다.
- "이 선이나 노드를 지워도 이 그림의 질문에 답이 되는가"를 묻는다. 답이 된다면 지운다.
