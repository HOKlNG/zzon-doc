## 개요

데모숍은 상품 전시부터 주문·결제·알림까지 담당하는 커머스 플랫폼이다. 이 문서는 시스템의 경계 —
누가 쓰고(액터), 무엇과 통신하는지(외부 시스템) — 를 고정한다. 내부 구조는 [전체 아키텍처 원장](#/architecture/landscape)에서 본다.

@diagram(context)

## 액터

- **구매자** — 웹·모바일로 상품을 탐색하고 주문·결제한다.
- **운영자** — 상품·재고·주문을 관리하는 내부 직원.

## 외부 시스템

| 시스템 | 용도 | 연동 방식 |
|---|---|---|
| 토스페이먼츠 | 결제 승인·취소 | REST API (동기) |
| 메일 서비스 (SES) | 주문 확인·알림 메일 | REST API (동기) |
| 물류 시스템 | 출고·배송 추적 | 이벤트 (비동기) |

> ❓ 미확인(q-001): 외부 PG는 토스 단일인가, 복수 연동 예정인가?

## 경계 원칙

- 결제 수단 정보는 시스템 내부에 저장하지 않는다 — PG 토큰만 보관한다.
- 물류 연동은 이벤트 기반 단방향이다. 배송 상태는 웹훅으로 수신한다.
