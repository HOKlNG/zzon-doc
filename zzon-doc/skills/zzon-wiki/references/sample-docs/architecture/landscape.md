## 개요

전체 아키텍처 원장은 시스템 경계와 도메인 구분을 그대로 두고, 그 안의 서비스와 저장소까지 한 장에 담은 지도입니다. 이 문서는 그림을 읽는 방법과 주문 한 건이 시스템을 지나가는 경로를 설명합니다. 자세히 보고 싶은 노드를 더블클릭하면 해당 문서나 상세 그림으로 넘어갑니다.

## 아키텍처

그림 1은 데모숍의 진입점부터 운영 기능까지 담은 전체 지도입니다. 요청은 왼쪽에서 오른쪽으로 흐릅니다.

@diagram(full-landscape)

### 진입 경로

요청은 CDN과 웹 방화벽을 지나 로드밸런서와 게이트웨이에 닿습니다. 웹 방화벽이 유일한 공개 진입점입니다.

### 도메인 서비스

주문, 상품, 회원, 검색 도메인은 각자 서비스와 그 서비스의 DB를 위아래로 둡니다. 도메인끼리는 서로 직접 호출하지 않습니다.

### 비동기 처리와 데이터 플랫폼

큐와 워커가 맡는 비동기 처리는 오른쪽 열에 있습니다. 이벤트 스트림에서 웨어하우스로 이어지는 데이터 플랫폼도 같은 열에 따로 둡니다.

### 운영 기능

시크릿 관리와 배포, 관측처럼 모든 도메인에 걸친 운영 기능은 아래쪽 띠에 모았습니다.

## 동작 흐름

주문 한 건은 다음 순서로 처리됩니다. 번호는 그림의 순번 배지와 같습니다.

1. 구매자가 CDN으로 접속합니다.
2. 웹 방화벽이 요청을 검사합니다.
3. 로드밸런서가 요청을 두 가용 영역에 나눕니다.
4. 로드밸런서가 요청을 게이트웨이로 전달합니다.
5. 게이트웨이가 요청을 주문 서비스로 보냅니다.
6. 주문 서비스가 토스페이먼츠에 결제 승인을 요청합니다.
7. 주문 서비스가 승인된 주문을 DB에 저장합니다.
8. 주문 서비스가 주문 완료 이벤트를 큐에 발행합니다.
9. 후처리 워커가 큐에서 이벤트를 꺼냅니다.
10. 후처리 워커가 확인 메일을 보냅니다.
11. 후처리 워커가 물류 시스템에 출고를 지시합니다.
