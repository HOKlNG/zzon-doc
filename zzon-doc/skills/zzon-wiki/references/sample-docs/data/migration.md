## 개요

데모숍은 스키마 변경을 Prisma Migrate로 관리합니다. 이 문서는 마이그레이션 파일을 만들어 배포하기까지의 절차와, 되돌리기 어려운 변경을 다루는 규칙을 정리합니다.

## 변경 절차

1. 로컬에서 스키마를 바꾸고 마이그레이션 파일을 만듭니다.
2. 마이그레이션 파일을 PR에 함께 올려 코드와 같이 리뷰합니다.
3. 배포 환경에서는 있는 파일을 적용만 하고 새로 만들지 않습니다.

## 규칙

컬럼 삭제나 타입 축소처럼 되돌리기 어려운 변경은 두 번에 나눠 배포합니다. 먼저 그 컬럼에 쓰지 않도록 배포하고, 다음 릴리스에서 컬럼을 지웁니다.

이미 만든 마이그레이션 파일은 고치지 않습니다. 잘못 만들었으면 되돌리는 마이그레이션을 새로 만듭니다.

대량으로 데이터를 채우는 작업은 마이그레이션에 넣지 않고 별도 스크립트로 돌립니다. 그래야 데이터 작업이 배포 시간을 늘리지 않습니다.

## 설정 참고

```bash
pnpm db:migrate:dev     # 로컬: 스키마를 바꾸고 마이그레이션 파일을 만든다
pnpm db:migrate:deploy  # 배포 환경: 있는 파일을 적용만 하고 새로 만들지 않는다
```
